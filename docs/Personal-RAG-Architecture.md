# Personal RAG Architecture

## Purpose

This document defines the architecture of the MIN Personal RAG system.

Its purpose is to transform accumulated knowledge into a searchable, traceable, and agent-accessible memory system.

---

# Vision

Conversations become documents.

Documents become knowledge.

Knowledge becomes memory.

Memory becomes intelligence.

# Architecture Layers

## Layer 1 — Source Knowledge

The origin of all knowledge.

Sources include:

- Conversations
- Notes
- Specifications
- Governance Documents
- Crystal Records
- Logic Tear Records

Output:

Knowledge Documents

---

## Layer 2 — Knowledge Base

Structured storage layer.

Primary Repository:

MIN Knowledge Base

Domains:

- Agent
- Governance
- Civilization
- Crystal
- Logic Tear

Output:

Structured Knowledge

---

## Layer 3 — Knowledge Graph

Relationship layer.

Purpose:

Connect documents and concepts.

Example:

Civilization Charter

↓

Three House Governance

↓

Agent Governance

↓

MIN Agent

↓

Crystal Registry

↓

Logic Tear

Output:

Connected Knowledge

---

## Layer 4 — RAG Layer

Retrieval layer.

Functions:

- Search
- Discovery
- Context Retrieval
- Reference Resolution

Purpose:

Provide relevant knowledge at query time.

Output:

Context Package

---

## Layer 5 — Agent Layer

Execution layer.

Components:

- MIN Agent
- Future Agents
- Governance Agents
- Knowledge Agents

Purpose:

Reason using retrieved knowledge.

Output:

Responses, Decisions, Actions

# Design Principles

### Traceability

Every important concept should have an origin.

### Discoverability

Knowledge should be searchable.

### Continuity

Knowledge should survive participant changes.

### Evolution

Knowledge should remain expandable.

### Preservation

Important concepts should not be lost.
